# 必要性与系统行为对照

仓库中的 `audit_test.mbt` 和 `acceptance_test.mbt` 固化了以下可复现实验，而非只用文字声称必要性。

基线按 score、id 排序为 `[a,b,c,d,e]`，页大小为 2。第一页取得 `[a,b]` 后，在它们之前插入 `zero`：

| 方案 | 第二次请求 | 合并结果 | 审计 |
|---|---|---|---|
| offset | 新数据的 offset=2 | `[a,b,b,c,d]` | 重复 b、遗漏 e |
| MoonPageFlow keyset | `after=(b 的键,id)` | `[a,b,c,d,e]` | 无重复、无遗漏、顺序正确 |

ORM 的页码接口适合静态报表和可跳页 UI，数据库流式 Cursor 适合占用同一连接顺序消费；两者都不能替代跨请求、不占连接、可序列化的稳定位置。本项目保留 offset 兼容入口，使用者可按业务一致性要求选择，而不是宣称所有场景都必须使用游标。

运行 `moon test` 可直接验证这组对照；`audit_traversal` 还能在真实迁移样本上报告重复、遗漏、意外记录和顺序违例。
